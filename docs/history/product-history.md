# Loom Product History

This file records the product story behind Loom. It is maintained as product
copy, not only as engineering history, because the origin explains the product's
current shape.

## Timeline

### 2026-04-13 · Original Loom

The earliest recoverable product brief defines Loom as a personal thinking tool
for macOS. The key image was not a generic notebook or chat window. It was a
loom: sources are held as structure, the user asks and judges, and thoughts are
anchored back to specific passages until a personal fabric of understanding
emerges.

Source: `docs/design/LOGO_BRIEF.md`

### 2026-04-15 · Epistemic Loom

The design canon sharpened the idea into an epistemic loom: a
reading-and-thinking environment where source-bound understanding is woven into
memory. This version made the core boundary clearer: Loom is not a dashboard,
landing page, or chat shell.

Source: `docs/canon/CURRENT_DESIGN_CANON.md`

### 2026-04-17 · Structural Mark And Foreground Object

The brand work moved away from decorative weaving and generic wordmarks. The
stronger direction was a structural mark: a stable system that can absorb local,
discontinuous thought into durable memory.

The homepage work reached the same conclusion compositionally. Loom needed one
dominant foreground object, not a dashboard of equal cards.

### 2026-04-24 · Material Archive And Frontispiece

The product explored a more tactile reading environment: source material,
frontispiece plates, vellum, paper rhythm, and restrained archival composition.
This period is useful as visual research, not as a skin to copy.

Source: `docs/design/MATERIAL_ARCHIVE_DIRECTION.md`

### 2026-05-02 · Substrate for Prose

The v4.1 definition reframed Loom as a stable substrate for prose and
source-backed work. AI became a summoned helper by role, not a decorative
always-on surface. The important object was still the user's durable source,
note, and draft record.

Source: `docs/canon/LOOM.md`

### 2026-05-31 · Personal Knowledge Display

The current direction is personal-first. Loom is Yiping's personal knowledge
display platform: learning paths, source resources, portfolio work, and process
records become source-backed pages. This personal version is the first real
product surface; the later goal is a platform that can serve everyone.

Source: `docs/canon/LOOM.md`, `README.md`

### 2026-06-02 · Verified Profile And Source Dossier

The personal surface became more concrete. Yiping's profile, memberships,
coursework, certificates, and source files started replacing abstract product
copy. This was the first clear movement from mark text toward picture assets and
source evidence.

Source: `docs/archive/ai-build-log/specs/2026-06-02-loom-verified-dossier-design.md`

### 2026-06-03 · Evidence Workbench

The homepage was tested as a live evidence workbench: source files, draft state,
answer provenance, and cited outputs appeared together. This clarified an
important boundary. The source chain is real and valuable, but it should not
become the whole public homepage.

Source: `docs/archive/ai-build-log/specs/2026-06-03-loom-evidence-workbench-homepage-design.md`

### 2026-06-04 · Personal IA And Asset-Led Upgrade

The current public IA became:

- About
- Education
- Experience
- Digital Me

This was a product correction. The homepage should present Yiping first and use
Loom as the trust mechanism underneath. Sources and Draft remain core Loom
layers, but they should not dominate first-level public navigation.

The asset-led upgrade also set the next quality bar: real profile images,
institution marks, document previews, certificates, coursework, projects,
process states, and Digital Me evidence should carry the story before long
explanatory text does.

### 2026-06-04 · Product Philosophy Distillation

The older metaphor layer was not discarded. It was separated from public UI copy
and distilled into product philosophy for design and engineering.

Library, Eyes, and Memory now name time relationships rather than modules. Loom
is treated as a strict machine metaphor: it holds tension and alignment while
the user judges. Source remains sacred. AI is summoned help, not the
protagonist. Panel, weave, and pattern remain internal cognitive units. Thought
Map remains a core verifier for whether understanding is actually forming.

Source:

- `docs/design/LOOM_PRODUCT_PHILOSOPHY_FOR_DESIGN_ENGINEERING_2026-06-04.md`

### 2026-06-04 · Personal Growth Spine

The product direction deepened from a static personal profile into personal
growth made inspectable. The key loop became:

Source -> Attention -> Question -> Judgment -> Practice -> Draft -> Output ->
Identity -> Next source

This makes About, Education, Experience, Digital Me, and Loom history parts of
one system. The goal is not only to show who Yiping is now, but to show how
sources, learning, work, drafts, and judgments changed him over time.

Source:

- `docs/design/LOOM_PERSONAL_GROWTH_MODEL_2026-06-04.md`

### 2026-06-04 · Product System Architecture

The direction was then formalized as a layered product system rather than a
simple showcase. The current model separates:

- public identity surface
- evidence and source layer
- growth and capability layer
- cognitive structuring layer
- AI and production layer

This is the product maturity bar for future work. A visual change is not enough
unless it deepens evidence, growth, judgment, Digital Me capability, or
source-to-output production.

## Why The Name Is Loom

The name is literal in the original brief. Loom is called Loom because the
product is meant to do what a physical loom does: hold structure, preserve
tension, align material, and let the maker focus on judgment.

The earliest mapping was:

- source documents are the continuous warp;
- user thoughts, AI responses, decisions, and drafts are the weft;
- the product handles alignment and memory so the user can decide what matters.

A later brand layer reads `lo` as logic and human judgment, and `om` as
machine-scale reach: recall, synthesis, adjacency, and wider visibility. That
is a semantic layer, not a strict acronym. The older canon explicitly says LOOM
is not an acronym.

## Product Story Line

Loom began as a personal thinking loom. It became a source-bound memory system.
It is now a personal knowledge identity platform, built first through Yiping's
reference instance and designed to become useful for everyone later.

The old versions should be treated as idea work and evidence. The current
version should integrate their strongest principles: atmosphere, restraint,
source-bound judgment, one dominant foreground object, and real assets that make
claims inspectable.

The same is true functionally. Earlier source shelves, anchors, AI passage
questions, panel/weave/pattern experiments, Draft workflows, and native capture
work are not discarded. They are filtered into the current product as reusable
capabilities: evidence shelves, citation-backed Digital Me answers, process
replay, source-to-draft handoff, compact Loom intro, and cross-shelf personal AI
canvases.

The current rule is: old concepts can guide ontology and behavior, but current
public pages should translate them into restrained, literal, inspectable product
surfaces.

The deeper rule is: each major Loom surface should show growth, not only status.
