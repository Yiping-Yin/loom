# Loom Verified Dossier Page System Follow-up

This follow-up extends the Verified Dossier Home direction across the downstream web pages.

Loom turns a person's materials, learning path, work, process records, and AI conversations into an inspectable, traceable, askable personal knowledge identity. It is first for Yiping, but the final product is for everyone.

The design language must feel professional, enterprise-ready, and refined. It should not read as a toy, demo, or decorative prototype. The page system should follow the restaurant-menu analogy: clear structure plus real desirable material beats decorative design.

## Product And Design Requirements

- Use real artifacts wherever possible: Yiping's real profile photo, institution marks, actual-looking course and source materials, document previews, source citations, and process records.
- Use high-fidelity file visuals for PDF, Word, PowerPoint, Excel, and Markdown artifacts instead of generic cards.
- Make the source-to-draft-to-answer chain visible: source material, extracted notes, draft work, AI answer, and citation trail.
- Preserve Home's current responsive and layout polish, then raise fidelity through document thumbnails, realistic previews, provenance rows, and page-to-page visual consistency.
- Keep the shared page system aligned across About, Sources, UNSW, Quantnet, WQU, Claude, and History.

## Downstream Page Scope

| Page | Purpose | Core evidence and artifacts | Required components |
| --- | --- | --- | --- |
| About | Present Yiping's verified identity dossier and explain Loom as a personal knowledge identity. | Real profile photo, bio notes, portfolio links, membership evidence, product story, selected source citations. | Dossier header, profile photo block, identity facts, membership marks, featured artifacts, cited biography notes. |
| Sources | Serve as the inspectable archive behind the dossier. | PDFs, Word docs, slide decks, spreadsheets, Markdown notes, imported conversations, source metadata, ingestion records. | Source library, file-type badges, document thumbnails, provenance rows, filters, citation-ready source detail panels. |
| UNSW | Show UNSW study as a traceable learning path, starting with ECON3202. | Course pages, lecture slides, tutorials, problem sets, notes, submissions, source-to-answer examples. | Institution header, course shelf, weekly timeline, document previews, source-to-draft-to-answer chain, citation panels. |
| Quantnet | Show skill proof for quant learning and interview preparation. | Python exercises, market reasoning notes, interview notes, project writeups, forum or course references. | Skill lane, artifact grid, code/file previews, reasoning notes, progress records, output summaries. |
| WQU | Track credential evidence and case-study outputs. | Program pages, assignments, case studies, certificates, spreadsheet or report artifacts. | Credential header, evidence timeline, file previews, case-study cards, citation rows, completion status. |
| Claude | Make AI conversations, prompts, and certificate evidence inspectable. | Claude course or certificate records, prompt notes, AI conversations, response drafts, persona memory records. | Conversation archive, prompt cards, certificate evidence, answer-with-sources panel, process records, model/provenance metadata. |
| History | Explain why Loom is called Loom and how the concept evolved. | Original Loom notes, Private Wiki milestones, design decisions, process records, release notes, screenshots. | Product timeline, decision log, before/after artifacts, cited process records, milestone cards. |

## Shared Components To Extend

- Top navigation shared by all Verified Dossier pages.
- Identity or section dossier header.
- Evidence lanes for source material, process, outputs, and AI interactions.
- High-fidelity file badges and document preview thumbnails.
- Source rows with citation and provenance metadata.
- Process records that show attempts, decisions, blockers, and outcomes.
- AI provenance panels that connect prompts, source citations, draft output, and final answer.

## Boundaries

This follow-up does not close live AI provider acceptance or installed importer acceptance. It scopes the next web-page design and implementation work needed after Home, and it should not be treated as final product completion until the downstream page system is implemented or deliberately re-scoped.
