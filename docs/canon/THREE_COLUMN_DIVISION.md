# Three-Column Division of Labor (RATIFIED 2026-07-08)

> Owner asked (with two artifacts: his real Finder tree for MATH 2991, and
> Atlas's "Auto Organize · right-click to edit template"): where does course
> classification live, and what is each column FOR. Design ran a 3-approach
> adversarial round; "Two planes, one spine" won (8.17, only zero-fatal-flaw
> verdict set). The owner ratified all three rulings below the same night.
> Supersedes the 2026-07-03 charter's one-liner; every future rail/IA design
> checks against this document.

## The division, one line

**Left = my notes organized my way · Center = my book · Right = the world's
real materials for this project, one step from reading.**

## Left column — the thinking plane (The Study Index)

What it is: the place everything STARTS. Courses (projects), ONE level of
groups inside a course (W 1…W n / Guide / Additional Resources), and the
chats/notes in each group in learning order. A group may quietly bind to a
real subfolder (the spine).

What it is never: a file list, a source/evidence area, a Finder clone.
(rail-rows-are-initiations law + the design-discipline "file browser clone"
refusal both stand.)

**Ruling ② (owner 2026-07-08): one-level nesting APPROVED.** This
consciously supersedes the 2026-04-26 sidebar-flattening precedent — that
cull's disease was file sub-pages of two coexisting shapes; groups are pure
containers, chats appear exactly once, and depth is capped at ONE by
construction (never deeper). The old V9 rule (no List sidebar) is formally
superseded by WORKBENCH_MACOS_STANDARDS §3 (native source list).

## Center column — the book

The owner's own document. The reader docks beside it; captured quotes land
in its body as loom://anchor evidence; provenance is a quiet chip. It is
never a classification surface, a file manager, or chrome's home. The
2026-07-08 division design changes NOTHING here — cover the chrome and it
must still read like the book.

## Right column — the material plane (The Bridge to the World)

What it is: the door through which the world enters this project — the
bridge verbs (Add files / Review / Browser) plus the **Materials tree**: the
course's bound REAL disk folder, rendered read-only through its
security-scoped ContentRoot (system file icons, Space = Quick Look, click =
open in the in-app reader). When a source is open, the bridge still yields
the column entirely (the right column IS the note while reading).

**Ruling ① (owner 2026-07-08): scope law v2.** The 2026-07-03 red line —
the bridge is NOT a duplicate list of this project's registered sources —
stands unchanged. The Materials tree renders the EXTERNAL WORLD (the bound
folder as it exists on disk), which is the owner's own "bridge to local
files" charter clause finally honored. These are different things; the
distinction is the law.

## The spine

Each group may bind to a subfolder of the course root (W 3 ↔ `W 3/`).
Consequences, by construction rather than by rules engine:
- Creating a course DERIVES its groups from the real folder's first-level
  subfolders (preview → accept). Organization already paid for in Finder is
  never paid twice.
- A note born from a W 3 file is born IN the W 3 group ("Note this file" →
  chat created in that group). Classification happens at birth, not by
  filing afterwards.
- Bound groups display the LIVE resolved folder name; renaming a bound
  group in LOOM is an explicit "Detach from folder".

## Auto Organize (the Atlas verb, native rules)

Typed, per-course template (week pattern / extra groups / exclusions / term
start date / route-new-drafts-to-current-week), defaults derived from the
real folder shape. Lives on the course's ··· menu as "Auto Organize" and
"Edit Template…". Everything is explicitly triggered with preview-before-
accept; re-runs propose diffs (new subfolder → proposed group; vanished
folder → dangling badge, NEVER deletion); templates never retroactively
rename existing groups; manual grouping stays first-class.

**Ruling ③ (owner 2026-07-08): LOOM never writes the owner's disk.** Both
escalations were REFUSED and recorded: (a) v2 physical filing (moving stray
files into subfolders) — refused; (b) writing course/week labels as real
Finder tags — refused. The ContentRoot read-only contract is structural.
Revisiting either requires a new explicit owner ruling against this refusal.

## Deletion semantics (containers are never owners)

Deleting a group returns its chats to the course; deleting a course
cascades its group entities and returns ALL chats to unfiled. No chat is
ever deleted by a container operation.

## Build sequencing (fixed at ratification)

Model fields + pure planners land immediately (no in-flight files). Rail
nesting lands as its OWN cut after Wave 2's flat verbatim sidebar migration
is green. The Materials tree mounts on W2-1's `.inspector` target — it is
never built twice on the condemned hand-rolled HStack.
