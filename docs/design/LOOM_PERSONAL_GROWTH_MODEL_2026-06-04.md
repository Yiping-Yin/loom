# Loom Personal Growth Model

Status: active product direction
Date: 2026-06-04
Scope: personal IA, Education, Experience, Digital Me, product depth

Loom should not be only a personal profile, portfolio, source library, or AI
interface. Its deeper product value is personal growth made inspectable.

The public product can show who Yiping is now. The deeper system should show how
Yiping became that person, what evidence supports that growth, what is currently
forming, and what the next growth direction is.

## Core Thesis

Personal growth is not a motivational story. It is a source-backed change in
judgment, capability, taste, and output over time.

Loom should make that change visible.

The growth loop:

1. Source
2. Attention
3. Question
4. Judgment
5. Practice
6. Draft
7. Output
8. Identity
9. Next source

This loop is the bridge between Loom's old cognitive philosophy and the current
personal knowledge identity product.

For the broader product architecture around this loop, read
`docs/design/LOOM_PRODUCT_SYSTEM_ARCHITECTURE_2026-06-04.md`.

## Why This Matters

Most personal websites show the final state:

- name
- school
- work
- projects
- certificates
- links

That is useful, but shallow. It does not show how the person thinks, learns,
changes, or builds judgment.

Loom should show the formation process:

- what sources shaped a direction
- what questions appeared
- what work was attempted
- what changed after practice
- what evidence proves capability
- what remains unfinished
- where the person is going next

This is the difference between a portfolio and a growth system.

## Growth Objects

### Growth Thread

A long-running development line, such as:

- mathematical economics
- trading systems
- programming for quantitative finance
- AI-assisted learning
- product design
- Loom itself

A growth thread connects sources, practice, projects, drafts, outputs, and next
directions.

### Learning Evidence

Evidence that a source has affected the person:

- annotated source
- coursework
- worked solution
- draft explanation
- cited answer
- project artifact
- certificate
- reflection or decision note

Learning evidence should be visible and inspectable, not hidden behind summary
copy.

### Judgment Change

The most important growth evidence is not only completion. It is changed
judgment:

- what became clearer
- what was corrected
- what became less naive
- what standards rose
- what choices changed

Loom should eventually model this through process notes, before/after drafts,
Digital Me explanations, and Thought Map state.

### Capability Proof

A capability is not a label. It should be backed by:

- source trail
- practice trail
- output artifact
- repeatable explanation
- Digital Me ability to answer from the trail

Education and Experience should both use this proof model.

## Page Implications

### About

About should not only introduce identity. It should show current direction as
the current state of a growth path.

Questions it should answer:

- Who is Yiping now?
- What is he becoming?
- What sources and work shaped that direction?
- What can a visitor inspect?

### Education

Education should be the clearest growth page.

It should show:

- institutions
- courses
- certificates
- coursework
- source-to-output process
- unfinished and active learning paths

UNSW should sit above ECON 3202. Courses are growth threads inside the
institution, not the whole education identity.

### Experience

Experience should show applied growth.

It should connect projects, competitions, work, and built systems to the sources
and practice that made them possible.

### Digital Me

Digital Me should demonstrate growth, not only answer facts.

It should be able to:

- explain a learning path
- compare early and current understanding
- cite the sources behind a capability
- replay the process behind a project or course output
- show what is still developing
- turn a topic into a growth canvas

### Loom History

Loom history is itself a growth thread.

The old versions are not failures or discarded drafts. They are evidence of
product learning: early philosophy, visual attempts, functional prototypes,
course evidence, asset-led correction, personal IA, and current integration.

## Design Standard

Every major section should answer:

What changed in the person, and what evidence lets us inspect that change?

If a section only shows static assets, it is not deep enough.

## Engineering Standard

Data should support longitudinal growth, not only static presentation.

Future models should be able to represent:

- source
- anchor
- question
- judgment
- relation
- practice artifact
- draft
- output
- capability
- growth thread
- next direction

This does not mean building every model now. It means not designing current UI
or data structures in a way that blocks this direction.

## Product Standard

Loom should help a person become more capable over time, and then make that
capability inspectable.

That is the deep product: not a better profile page, not a prettier note app,
and not a louder AI assistant, but a system where personal growth becomes
source-backed, visible, and reusable.

This means display is only the first layer. The deeper layers are evidence,
growth, cognitive structure, and AI-assisted production.
